# Возможности и архитектура приложения

Проверено по mobile main c977aed и контракту backend 23.11.2026.

## Основной сценарий

Материал → режим → ожидание/прогресс → результат. Материал вводится текстом или выбирается системным диалогом как TXT/PDF. Выбранный файл можно убрать и заменить. Список режимов загружается с сервера; названия и описания задаёт приложение.

Пять режимов: краткий конспект, подробный конспект, объяснение простым языком, ключевые термины, вопросы для самопроверки.

Результат прокручивается, копируется целиком, отправляется через Android «Поделиться» вместе с названием режима. Сохранение TXT/Markdown открывает системный выбор места; кодировка UTF-8, имя по умолчанию содержит режим и дату. «Режимы» сохраняет материал, «Новый материал» начинает новый сценарий.

## Ограничения

- Введённый текст: 1–24 000 Unicode-кодовых точек, не только пробелы.
- TXT/PDF: максимум 10 МиБ. TXT: UTF-8 и Windows-1251 на сервере.
- PDF: нужен текстовый слой, поддержка сканов/OCR и снятие пароля отсутствуют.
- Обычные text/process и materials/process ограничены 10 000 символов. Для длинного материала клиент использует jobs/text или jobs/materials.
- Фоновая обработка: до 24 000 символов, 10 000 токенов и 6 частей. Ограничение токенов может сработать раньше символьного.
- Для файла длину извлечённого текста определяет сервер. Переход к jobs происходит после распознанной ошибки длины обычной обработки.

Точные серверные ограничения: [OpenAPI](https://github.com/study-ai-assistant/backend/blob/main/docs/api/openapi.yaml).

## Устройство клиента

- MainActivity / StudyViewModel: точка входа, Compose, жизненный цикл.
- StudyFlow: материал, режим, запрос, результат, отмена и повтор; зависимости запросов подменяются в тестах.
- StudyApi: HTTP и разбор ответа; BackgroundProcessor: создание задания и опрос статуса.
- MaterialModesContent, LongProgressContent, ResultContent: экраны.
- ServerSettings: сохранённый адрес сервера.
- ui/theme: цвета, JetBrains Mono и общие компоненты.

Ключ LLM хранится только на сервере. GET /health проверяет доступность backend, но не доказывает работоспособность LLM.

## Ожидание и ошибки

Таймаут обычной обработки — 90 секунд, соединения — 10 секунд. Фоновое задание опрашивается с учётом Retry-After; POST не повторяется автоматически. Отображаются очередь, число частей и ошибки, включая истёкшее задание и лимит провайдера. Оценка времени показывается только при наличии данных; число из макета не является настоящим таймером.

Отмена прекращает ожидание на клиенте; сервер может продолжать работу. Поздний ответ не должен заменять новый запрос. Поворот сохраняет состояние StudyViewModel. Восстановление после уничтожения процесса не гарантируется.
