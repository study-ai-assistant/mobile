# Работа с Figma

Правила для подкоманды design и для всех, кто использует макеты.
Цель — чтобы любой участник за минуту находил нужный экран, а разработчик mobile получал макет, по которому можно сразу писать код.

> Ссылка на Figma-проект: **ЗАПОЛНИТЬ** (ответственный: руководитель проекта).

## 1. Файлы

В Figma создаётся один проект (Project) «ИИ-помощник для учёбы» с четырьмя файлами:

| Файл | Что внутри | Кто правит |
|---|---|---|
| **Wireframes** | черновые схемы экранов без цвета и стилей, user flow | design |
| **UI-kit** | цвета, типографика, отступы, иконки, компоненты (кнопки, поля, карточки) | design |
| **Design** | финальные макеты экранов, собранные из компонентов UI-kit | design |
| **Prototype** | кликабельный прототип основных сценариев для демо и проверки | design |

UI-kit подключается к файлам Design и Prototype как библиотека (Assets → Libraries). Цвета и текст в Design задаются только стилями и переменными из UI-kit, без «ручных» значений.

## 2. Страницы внутри каждого файла

| Страница | Назначение |
|---|---|
| **Cover** | обложка: название файла, статус (Черновик / На review / Готово), дата обновления, ответственный |
| **Flows** | пользовательские сценарии: стрелками связанные экраны |
| **Screens** | экраны, сгруппированные по сценариям (секции) |
| **Components** | компоненты (в UI-kit — основные, в остальных файлах — локальные черновики) |

Дополнительно можно завести страницу `Archive` для старых вариантов. Удалять старые варианты не нужно — переносите их туда.

## 3. Именование

Общие правила: латиница или русский — выбрать один вариант для всей команды (ЗАПОЛНИТЬ), слова через пробел, без «Frame 123» и «Copy».

**Экраны (фреймы):** `<Сценарий> / <Экран> / <Состояние>`

```
Upload / Выбор файла / Default
Upload / Выбор файла / Error
Mode / Выбор режима / Default
Result / Конспект / Loading
```

**Компоненты:** `<Категория> / <Название> / <Вариант>` и свойства через Variants:

```
Button / Primary / Default
Button / Primary / Disabled
Input / Text / Error
Card / Result
```

**Стили и переменные:** `color/primary`, `color/text/secondary`, `text/heading/h1`, `text/body/regular`, `spacing/16`.

## 4. Доступы

| Роль | Права в Figma |
|---|---|
| Дизайнеры (команда design) | **Editor** |
| Разработчики (mobile, backend) | **Viewer** (с возможностью смотреть Dev Mode, если доступен) |
| Руководитель проекта | Editor (владелец проекта) |

Доступ выдаётся на уровне Figma-проекта, а не отдельных файлов. Ссылки на макеты не публикуются за пределами команды.

## 5. Задачи дизайна и передача макетов разработке

Задачи, которые выполняет дизайнер, создаются в репозитории mobile по шаблону **«Задача дизайна»**:

- название начинается с префикса **`[DESIGN]`**, например `[DESIGN] Wireframes: экран загрузки материала`;
- на задаче стоит метка `design`, в поле Team на доске — **Design**.

Порядок передачи макета:

1. Дизайнер доводит экран до статуса «Готово» по чек-листу ниже.
2. В Issue на GitHub добавляется **ссылка на конкретный фрейм** (ПКМ по фрейму → Copy/Paste as → Copy link). Ссылка на весь файл не подходит.
3. Дизайнер упоминает разработчика mobile в комментарии Issue.
4. Вопросы по макету задаются комментариями в Figma прямо на фрейме; итоговое решение дублируется в Issue.
5. Если макет меняется после передачи — дизайнер пишет в Issue, что изменилось.

> **Ссылка на фрейм обязательна в каждом Issue по дизайну и mobile-интерфейсу.** Без неё задача не может перейти в статус Sprint Todo.

## 6. Чек-лист «макет готов»

- [ ] Экран лежит в файле **Design** на странице **Screens** в правильной секции
- [ ] Фрейм назван по правилам (`Сценарий / Экран / Состояние`)
- [ ] Отрисованы все состояния: обычное, загрузка, ошибка, пустое (если применимо)
- [ ] Используются только компоненты и стили из **UI-kit**, нет «ручных» цветов и шрифтов
- [ ] Применён Auto Layout, отступы кратны шагу сетки (ЗАПОЛНИТЬ: 4 или 8 px)
- [ ] Тексты реальные или правдоподобные, без «Lorem ipsum»
- [ ] Экран связан в прототипе (если входит в сценарий)
- [ ] Учтены размеры экрана: базовый макет (ЗАПОЛНИТЬ: например 360×800) и проверка на маленьком экране
- [ ] Контраст текста достаточный для чтения
- [ ] Ссылка на фрейм добавлена в Issue, разработчик mobile просмотрел макет и вопросов нет
- [ ] На странице Cover обновлены статус и дата
