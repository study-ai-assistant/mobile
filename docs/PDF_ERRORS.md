# Ошибки загрузки PDF — #34

Контракт: backend PR #38, commit `d9bd656a80ad5bbd6627227f1610bd1dcc940e94`.
Реализация для интеграционной проверки: backend PR #40,
commit `9ac27e1e7b76867358e14731b49ff06613370bab`.
На момент подготовки оба PR ещё открыты; в backend/main PDF пока не поддерживается.

| Причина | HTTP | Сообщение пользователю |
|---|---|---|
| Скан, нет текста | 422 | В PDF нет текстового слоя: возможно, это скан. Выберите PDF с выделяемым текстом или TXT-файл. |
| Пароль | 422 | PDF защищён паролем. Выберите доступную вам копию без пароля или другой файл. |
| Повреждение | 422 | Не удалось прочитать PDF: файл повреждён. Скачайте его заново или выберите другой файл. |
| Более 50 страниц | 413 | В PDF больше 50 страниц. Выберите документ до 50 страниц. |
| Более 10 МиБ | 413 | Файл слишком большой. Выберите файл размером не больше 10 МиБ. |
| Более 10 000 символов | 413 | В материале больше 10 000 символов. Выберите более короткий материал. |
| Таймаут разбора | 504 | Не удалось разобрать файл вовремя. Выберите меньший или более простой PDF. |

## Как устроено

`MaterialErrorMessages` сопоставляет HTTP-статус и известный `detail` из Problem.
Контракт пока не содержит машинных кодов ошибок; при изменении текстов backend
нужно обновить таблицу. Неизвестный detail/HTML/повреждённый JSON не выводятся:
показывается безопасное общее сообщение по HTTP-статусу. Тело ошибки ограничено
64 КиБ, соединение освобождается. JSON-обработка текста и /health не менялись.

Добавлен недостающий импорт StudySpacing: без него текущий main не собирался.
Ошибки отображаются существующим компонентом ErrorMessage из темы.

## Проверка

- `testDebugUnitTest`: все примеры PDF из контракта, неизвестные и некорректные
  ответы, предел размера тела ошибки, ошибки чтения ответа, сохранение ошибок TXT.
- `LivePdfErrorsTest`: мобильный HTTP-клиент проверен с настоящим PDFBox/backend
  из PR #40 на шести файлах: изображение без текста, пароль, повреждение, 51 страница,
  размер больше 10 МиБ, текст больше 10 000 символов. Все шесть сообщений совпали.
  Ключ LLM не нужен: эти запросы отклоняются до генерации.
- `PdfErrorsUiTest`: отображение шести сообщений, сохранение файла, повтор и возврат.
  Скриншоты UI показывают тестовые ответы; это не скриншоты реальной генерации LLM.

Для повторения интеграционной проверки задайте PDF_TEST_BASE_URL (адрес backend)
и PDF_TEST_FIXTURES (каталог с тестовыми PDF из пакета), затем выполните:

```powershell
.\gradlew.bat testDebugUnitTest --tests '*LivePdfErrorsTest' --rerun-tasks
```

Без этих переменных live-тест пропускается; обычные тесты не требуют сервера.
