# Проверка экрана mobile#6

Основа — ветка Арсения `feature/mobile-setup` (PR #11). Ветка этой задачи:
`feature/6-server-screen`. Публиковать как Draft до проверки на устройстве.

## Запуск

1. Открыть mobile в Android Studio, дождаться Gradle Sync.
2. В соседнем backend использовать `feature/server-base`, JDK 21 и выполнить
   `.\mvnw.cmd spring-boot:run` (Windows) или `./mvnw spring-boot:run`.
3. Адрес задаётся только в `api/ServerConfig.kt`. Для Android Emulator уже указан
   `http://10.0.2.2:8080`; для телефона нужен IP компьютера в общей Wi-Fi сети.
4. Запустить debug-вариант приложения. HTTP разрешён только в debug.
5. На Android 17/API 37 при первом запросе разрешить доступ к устройствам
   поблизости (ACCESS_LOCAL_NETWORK), затем повторно нажать кнопку.
   Отказ показывает подсказку; запрос без разрешения не отправляется.

## Ручная проверка

- «Проверить связь с сервером» показывает `status = ok`.
- На API 37 проверить первый запрос разрешения и отказ. После разрешения
  повторная проверка должна вернуть `ok`. На API 26–36 этот запрос не нужен.
- Остановить backend: сообщение об ошибке, приложение продолжает работать.
- Отправить пустой/пробельный текст: ошибка валидации без сетевого запроса.
- Текст длиннее 10 000 Unicode-символов: ошибка валидации.
- Ввести материал и нажать «Отправить»: пока запрос выполняется, поле и кнопки
  отключены, виден индикатор ожидания. Повторной отправки автоматически нет.
- В текущем скелете backend POST отсутствует: ожидается понятное сообщение
  «Обработка текста на сервере пока не подключена», а не выдуманный ответ LLM.
- После backend#8: `POST /api/v1/text/process` отправляет JSON `{text, mode}`
  с `mode = SHORT_SUMMARY` и показывает строку `result` из ответа.
- Проверить ошибки 400, 413, 502 и неверный JSON; текст введённого материала сохраняется.
- При повороте экрана введённый текст сохраняется. Ожидание отменяется на уровне UI,
  POST автоматически не повторяется; сервер мог продолжить уже отправленный запрос.

## Проверки сборки

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

`StudyApiTest` проверяет реальный HTTP-обмен с локальным тестовым сервером JVM:
JSON/UTF-8, режим, успешные ответы, ошибки, недоступность и лимит Unicode.
Для JVM-тестов добавлена реализация `org.json`; Android использует платформенную.

Задача не считается Done до запуска на устройстве, review, слияния и показа
полного сценария с настоящим backend/LLM на итогах спринта.
