# Подключение телефона к серверу (#33)

1. Запустите backend на ноутбуке. Подключите телефон к той же Wi-Fi-сети.
2. Узнайте IPv4 ноутбука командой `ipconfig` (например, 192.168.1.10).
3. Установите debug APK. На первом экране нажмите «Адрес сервера».
4. Введите `http://192.168.1.10:8080`, нажмите «Сохранить».
5. Нажмите «Проверить связь с сервером». На Android 17 при запросе разрешите
   доступ к локальной сети и нажмите проверку ещё раз.
6. Ожидаемый ответ — «Сервер доступен: status = ok». Он подтверждает доступ
   к серверу; готовность LLM проверяется отдельной отправкой материала.
7. Последовательно проверьте все пять режимов. Для каждого нужен реальный
   результат от сервера. Перезапустите приложение и убедитесь, что адрес сохранён.

Для стандартного эмулятора адрес ноутбука — `http://10.0.2.2:8080`.
`localhost` на телефоне указывает на сам телефон, а не на ноутбук.
Вводится только адрес с портом: без `/health`, `/api`, паролей и параметров.
При смене сервера введённый текст сохраняется, старый результат и список
режимов сбрасываются, режимы загружаются с нового сервера.

HTTP разрешён манифестом только в debug. Release использует HTTPS; попытка
сохранить HTTP-адрес в release выдаёт объяснение. Защита release не ослаблена.

Если связи нет: проверьте адрес/порт, что сервер слушает сетевой интерфейс
ноутбука, разрешение приложения на локальную сеть и правило брандмауэра для
порта backend в частной сети. Брандмауэр целиком отключать не нужно.
Некоторые Wi-Fi-сети изолируют устройства друг от друга.

Ключ LLM хранится на backend. В приложение его вводить не нужно.

Этот текст необходимо перенести в wiki «Сборка и запуск». Проверку реального
телефона и всех пяти режимов отмечает исполнитель после фактического прогона.
